# Bloomreach system events: condensed reference

Source: Bloomreach Engagement documentation, "System events" (updated 2026-09-11). Index at https://documentation.bloomreach.com/engagement/llms.txt. Condensed for the agents; consult the source for detail. System events exist in every project without integration; custom events are client specific.

## Catalogue of system events and their attributes
- `session_start`: tracked on website visit. Attributes: city, state, country, latitude, longitude, source, referrer, campaign_id, utm_campaign, utm_source, utm_medium, utm_content, utm_term, gclid, ip, device, os, browser, location, path, plus SDK ping fields activity, created, last_update. Deprecated custom additions: page_load_ms, screen_height, screen_width, screen_resolution, version.
- `session_end`: generated 20 minutes after the last ping; timestamp is last ping plus 30 seconds; same attributes as session_start plus `duration` (seconds). Ghost sessions can occur when a sleeping browser wakes and pings without a page_visit.
- `first_session`: derived from the first session_start.
- `page_visit`: disabled by default, enabled via SDK track options. Attributes: device, referrer, os, location, browser. Not generated on the Bloomreach CDN survey or consent pages.
- `campaign`: generated by email, SMS, MMS, WhatsApp, RCS, push, webhooks, ads. Key attributes: status, campaign_name, campaign_id, action_type (email, sms, webhook, ads, browser notification, mobile notification, transactional_email, split, facebook message), action_name, action_id, integration_id, integration_name, integration_type, campaign_policy, consent_category, subject (always default language variant), language, recipient, sent_timestamp, message, message_id, comment, error, code (SMTP), cumulative, ip, user-agent, url, city, country, latitude, longitude, sending_ip, state, type, xpath, template_id, template_name, audience_id, operation, number_of_message_parts, sender, status_code, preset_channel, platform. A/B split nodes add new_choice, variant, variant_type, variant_id. Weblayers in scenarios track both campaign (action serve) and banner (action show).
- `campaign.status` values: enqueued, enqueue_failed, suppressed, delivered, opened, clicked, soft_bounced, hard_bounced, preblocked, revalidated, complained, unsubscribed, sent, failed, closed, incoming_message, rejected, success, aborted, read. Renamed in release 1.173: dropped to soft_bounced, bounced to hard_bounced, rejected to preblocked; filters were migrated from equals to in with both names. Which statuses each channel produces differs (email has the full bounce set; SMS and push mostly sent, delivered, clicked, failed).
- `notification_state`: mobile SDK push token state. Attributes: push_notification_token, platform (android, huawei, iOS), valid, description, application_id, device_id. Events expire after 90 days; the project must allow the event type or push stops working.
- `survey`: question, answer, interaction, survey name, survey_id, question_index.
- `merge`: source_internal_ids, destination_internal_id, original_external_ids, final_external_ids, requested_ids.
- `ab test`: variant, variant_id, location, device, os, browser, name, banner_id or experiment_id.
- `experiment`: experiment_name, experiment_id, variant_name, variant_id, action (show, close, submit, click), location, path, device, os, browser.
- `anonymization`: source, access_group_id, user_id.
- Also present in Data Manager exports as Bloomreach-generated: banner, consent, retargeting, recommendation, managed_endpoint, double_opt_in, data_capture, store_visit, inbound_call, outbound_call, paper_catalogue, support_ticket, return, loyalty_update, monitoring (client custom events may share these names).

## Consequences for the tooling
- The known system event list in `src/domain/bloomreach.ts` should become a seed of system event definitions with attribute lists, not just names, so QA can validate system events (status enums, expected attributes) instead of merely suppressing unexpected_event for them.
- `campaign.status` and `campaign.action_type` are natural enums; `campaign.status` is the discriminator for post-campaign use cases (delivered vs clicked vs bounced).
- `notification_state` expiration is 90 days by platform rule; the expiration fixture sets 100 days, which is a client override to keep.
- `page_visit` off by default explains its absence from many exports; missing_event for it should be suppressed unless the definition marks it enabled.
- Location attributes from IP are unreliable for latitude and longitude; do not build variants or requirements on them.
