## Real-client review script

Goal: load one real Bloomreach project and judge whether the app replaces the sheet. About 90 minutes.

1. Start locally: `npm run dev`, open `http://127.0.0.1:3000/tracking-plan/`. Create the client and an empty project (industry set, it drives the template filter).
2. Pull from the Bloomreach project, in this order: Data mapping export (`data-mapping.json`), Expiration settings export, Data Manager customers export, Data Manager events export, a Customer events export of one to two days (`customer-events-export.json`). Import each on the Import page, confirming the diff (D-04). Getting started should tick the first steps as you go.
3. Retype properties the mapping leaves generic (money, number, boolean) on the Properties page; where one attribute name means different things per event, add a second definition and pick it on the event link (Properties page, definitions row).
4. Run the comparison (QA runs page): read the Findings by severity; acknowledge the ones that are known. Check that the Events page certification column matches your understanding of which events are clean.
5. Open three event cards (one custom, one sdk, one platform): triggers with a page URL and screenshot, expected payload, codegen snippets, history, comments.
6. Use cases: on the Templates page filter by the client's industry and channel, instantiate two or three templates; walk the mapping dialog for a system event the client names differently; check the requirements matrix and the narrative.
7. Share: Settings, generate a `comment` link, open it in a private window, post a comment as the client, find it internally with the via-share badge. Download the JSON and HTML and search them for anything you would not send to the client.
8. Exports: `data-mapping.json` and `expiration-settings.json` back out (byte-equivalent on an untouched project), events and properties CSV, `backup.json`; restore the backup as a copy and compare counts.
9. MCP: with `.mcp.json` pointing at the same DB, ask an agent for `get_tracking_document` and `list_findings` and judge whether the output is what an implementing agent needs.
10. Note every place you reached for the sheet instead; those are the phase 5 backlog.

Take a `backup.json` of the loaded project at the end and keep it outside the repo (client data).
